# JewelryB2C3 — end-to-end review (2 October 2026)

**Scope:** the customer site `http://proto/JewelryB2C3/` and the Admin `http://proto/JewelryB2C3/admin/`, as deployed (commit `73e01e4`), plus the code and the server behind proto (tron).

**How it was reviewed**

- Live customer site on proto: landing page, sign-in dialog, legal pages, mobile (375 px and 360 px), HTTP headers, public endpoints, page weight, console. No design, movie, 3D request or email was triggered on proto (live mode = paid).
- Live Admin on proto, signed in: Dashboard, Sessions, a session detail with 3D, Users, AI Prompts & Params (model configs, material pricing, AI prices), plus the Admin API data.
- The full customer journey (sign-in → four designs → select → Customize → Bag → Checkout) on the local server in mock mode, desktop and phone widths. Same code as proto.
- Server inspection on tron over SSH: systemd unit, nginx, `.env`, disk, memory, logs, backups, databases.
- Code: authentication, registration and mail, quotas, uploads, path handling, the Admin, tests (137, all passing).

**Not done:** load testing, an external penetration test, a live-provider run, an email deliverability test.

---

## 1. Verdict

The product works end to end and is in good shape for what it is today: an internal preview used by one tester from three internal IPs. The architecture is clean (services behind one context, no globals, base-path discipline with tests, mock/live separation with a typed cost confirmation, persisted queues and stages, versioned model/pricing configs, soft deletes, numbers that are never invented). The Admin gives real operational visibility.

It is **not ready for outside customers**. The gaps are not in the design flow itself but around it: a 6-digit shared admin password over plain HTTP, no rate limiting anywhere, a quota that does not count the expensive requests, public API documentation, no backups or monitoring, a server with 1 GB of swap in use and ~40 rings of disk left, and a checkout that is a dead end. One customer-visible bug was found (Bag shows "pricing changed" on every new line) — it is a regression from yesterday's material-pricing change and is a one-line fix.

**Live numbers at review time:** 10 live sessions (+3 mock), 1 customer account (12 of 50 generations used, ≈$23.52 of AI at list prices), 15 3D requests, 7 Hi3D models (2.2 GB). Funnel: Started 10 → Generated 10 → Customize 9 → Bag 8 → Checkout clicked 0.

### 2.8 Product recommendation: the Gallery as an entry point — **implemented 2 Oct**

The "COMING SOON" tiles (U2) are now a real entry into the design flow, built as recommended:

- **Tiles are real XJet designs.** An admin adds a design from its session page (Sessions → "Show in gallery", or "Use in gallery" under any option); the tile shows that design's selected image; the Admin **Gallery** tab sets the order and shows how many customers started from each tile. The underlying design keeps its full batch of four images.
- **One tap opens a large preview** with aspirational copy — *"Love this design? Make it yours."* / *"Inspired by this look? Start here and make it your own…"* — and two actions, **Make it yours** and **Back to gallery**. Single tap is the primary interaction on every device; no double-click is needed.
- **Make it yours, signed in:** the Design screen opens with the original batch of four images, the gallery image already selected, and the customer continues normally — refine, 360° movie, Customize, metal, size, Bag.
- **Make it yours, not signed in:** the normal sign-in flow opens; the chosen design is remembered and opens right after sign-in (also across the verification-email link, when it is opened in the same browser). The customer never has to find the gallery design again.

Decisions taken while implementing (edits to the original recommendation):

1. **The customer gets a copy, not a link to the XJet design.** The batch's four images are copied into a new design owned by the customer, with the gallery image selected. Refinements, the movie and Customize therefore never touch the XJet original, removing a design from the gallery never breaks a customer's design, and the Admin keeps a clean origin trail ("Started from gallery · R-1013-B", a `gallery_started` event, `origin` / `source_ring_id` in the session data).
2. **Nothing is generated or charged** by "Make it yours" (no AI request, no quota). Costs start only when the customer refines or proceeds to the movie, as with any design.
3. **Only the batch behind the gallery image is copied** (its four siblings), not the whole refinement history of the XJet design — that is what the customer saw and chose.
4. **An empty gallery hides its tiles** behind one line ("New designs are being added to the gallery") rather than placeholders.
5. **The Design screen says why there are four images already**: "Your gallery pick and its three siblings — select your favourite", and the prompt bubble is labelled "Started from the Inspiration Gallery".
6. **Movies travel with the copy.** A 360° movie XJet already made for an option is copied too, so Customize shows it immediately and no second movie is generated or charged.
7. **No duplicates.** Starting the same gallery design again opens the customer's existing copy, moved to the top of My Designs.

Follow-ups: curate 6–8 strong live designs (mock-mode designs can be added but look like placeholders); consider a short caption per tile; split the Dashboard funnel by origin (prompt vs gallery) once there is traffic.
